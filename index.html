01) Explain what is serverless architecture?

A serverless architecture is a way to build and run applications and services without managing infrastructure. The term “serverless” indicates that there are no servers, but there are servers and hardware infrastructure. But the cloud service provider is responsible for configuring, maintaining and managing servers instead of you. This means developers are able to concentrate on coding and not hardware tasks.

One common use case of serverless architecture is the development of chatbots and virtual assistants. Here serverless functions can respond to user requests through messaging platforms or voice interfaces and automatically balance the requests according to the number of users. Serverless architecture is also widely used for real-time data processing, as serverless functions can process streaming data immediately for purposes such as analytics, system monitoring, and generating alerts without requiring organizations to manage dedicated processing servers.

Even though the serverless architecture has its benefits, it also has its own limitations. One of the main issue happens when a cloud service provider has to run a function that has not been used for long time. This situation may lead to a small delay in the execution process. Another problem is vendor lock-in, as the applications may become strongly connected to services and tools provided by a specific cloud provider. Also, monitoring and debugging many different functions that build the application may be more complicated than managing the regular application.

    • 02) List some benefits of IaC (Infrastructure as Code) for modern software development

    Infrastructure as Code (IaC) is a method of managing and provisioning computer infrastructure using code and configuration files instead of manually setting up servers, networks, databases, and other resources.

    One benefit of IaC is automation. Automation means that infrastructure can be created, configured, and managed automatically using code, rather than requiring someone to perform each task manually. For example, without IaC, a developer might have to manually create a virtual server, install software, configure the network, set security settings, and connect a database. This can take a lot of time and may lead to mistakes. With IaC, the developer writes a configuration file that describes what infrastructure is needed. An IaC tool can then automatically create and configure those resources.

    Another one is consistency. The same infrastructure configuration can be used through development, testing, and production environments. With IaC, the infrastructure configuration is written as code, so same setup can be used in different stages of software development in same way.

    Version control is another benefit of this. That mean code can be stored in a tool like Git. This allows to keep records of previous versions and maintain the code easily. This is very useful in a situation where latest version of code is not functioning as expected due to some error. Then we can get the working previous version and run the application from that version without any issue.

    Faster deployment is another main use case in IaC. This allows to create and configure quickly than doing things manually. Instead of spending hours setting up servers, networks, databases, and security settings one by one, a team can use IaC code to automatically deliver all the required resources.

    IaC helps minimize mistakes that can happen when people manually configure servers and other infrastructure. Manual configuration require same operation to be done several times to verify the configuration. When human do such work there is possibility to happen human errors for eg forgot the steps accidently etc. With IaC, these configurations are written in scripts or configuration files. These scripts can be run automatically which helps to reduce human errors.

    • 03) Describe shortly what is Kubernetes and what alternatives are there?

    Kubernetes (K8s) is an open-source platform that is designed to deploy, manage, and scale containerized applications. Among its tasks are launching and destroying containers, allocating the workload among servers, scaling the applications according to the need, and restarting the containers which fail to function. In simple words, Kubernetes assists organizations in handling large volumes of containers.

    There are some alternatives to Kubernetes that may be used for container orchestration. Docker Swarm is a more straightforward container orchestration platform that is incorporated into Docker and is good to use for applications that do not require the complexity of Kubernetes. Amazon Elastic Container Service (ECS) is a container orchestration service from AWS and it is good to use for the organizations working with the AWS ecosystem. Another option is HashiCorp Nomad – a tool that can handle not only containers but other types of workloads and offers a simple way of orchestration. Red Hat OpenShift is one more alternative; however, it is based on Kubernetes and offers extra features such as security and enterprise capabilities. Thus, there are alternatives to Kubernetes, depending on the needs of the organization.

    Kubernetes (K8s) is an open-source platform used to deploy, manage, and scale containerized applications. It automatically handles tasks such as starting and stopping containers, distributing workloads across servers, scaling applications when demand changes, and restarting failed containers. In simple terms, Kubernetes helps organizations manage large numbers of containers efficiently.

    • 04) List some information security risks when using third party (for example Docker) containers?

    The usage of containers of third parties like Docker containers may carry a number of information security issues. First of all, a container may be out of date because it may include outdated software and known vulnerabilities that can be exploited by an adversary. Second, there is a chance of getting a malicious or compromised image because of the presence of malware or backdoors. Another information security issue is the software supply chain risk, in which the adversary may infect dependencies and legitimate images before being applied to an organization's use. Bad container configuration, such as granting containers extra permissions and using root, may be another information security threat. In addition, container runtime and the host operating system may have certain vulnerabilities that may be used by the adversary to break out of the container and get into the host. Containers may leak sensitive data such as passwords and other credentials because of configuration files, environment variables, and logs.
